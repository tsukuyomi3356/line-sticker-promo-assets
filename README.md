## 新作LINEスタンプ投稿画像・再利用プール運用（2026-11-19追加）

新作スタンプをThreadsで初めて紹介する場合は、**本人の販売済みLINEスタンプ作品ID・公式販売ページ・実際の収録絵柄／文言を確認してから**、その作品の新しい「トーク使用例画像」を作成する。公式作品から離れた架空のスタンプを描いて販売物と誤認させない。

- **初回制作**：トーク使用例画像は最低1枚、できれば場面の異なる2～4枚。別途、全スタンプ一覧画像1枚を用意する。初登場の新規画像制作は最大5作品/日という既存上限を維持する。
- **保存先**：新規登録分は `stamps/reuse/<sticker_id>/talk-example-01.jpg`、`talk-example-02.jpg`、`catalogue-01.jpg` など。既存の `stamps/conversation-...` と `stamps/daily-...` は削除・改変しない。
- **登録条件**：各画像に作品ID・種類（conversation/catalogue）・実ファイルのパス／SHA-256・素材の出典／利用権・販売URL・制作日／確認日・目視確認済みの状態をマニフェストで記録。GitHubに画像の実バイナリが存在し、公開HTTPS画像URLを読み出せる場合に限り再利用プールへ追加。ファイル名や生成予定だけで「追加済み」としない。
- **投稿セット**：1枚目＝同作品のトーク使用例、2枚目＝同作品の全スタンプ一覧。両画像の `sticker_id` と返信末尾の `https://line.me/S/sticker/<sticker_id>` を一致させる。
- **使い回し**：別日への再利用は許可。ただし日本時間の**同日内に、同じ画像（同じSHA-256、別URLの同一画像、実質同じビジュアル）を2回使わない**。当日の予約済み／投稿済み画像も先に確認する。画像の再圧縮・小変更は別画像と数えない。同じ作品の一覧画像が1種類しかない場合、同日2投稿目にはその一覧を再使用しない。
- **文章**：親投稿・返信の両方を毎投稿ごとに新しい文章にする。構成・切り口・具体的な利用場面を変え、コピペや語尾だけの変更を禁止。
- **投稿ゲート**：既存Threads投稿、Buffer予約、GitHub/Cloudflareキューと当日使用履歴を照合する。2枚セットが揃わない、作品ID／権利が不明、重複チェック未完了なら `blocked` とし、投稿・予約しない。
- **更新範囲**：このREADMEは運用指示。画像自動生成、GitHubへのアップロード、使用履歴照合、実投稿は別途実装・検証が必要。指示書の変更だけで自動処理が稼働したとは扱わない。

## 22:15 翌日投稿準備との連携（2026-11-19追記）

- ChatGPTの毎日22:15 JSTのThreads翌日18件準備タスクで、作品・投稿案を確定した直後にこのリポジトリの実画像ファイルと作品別マニフェストを照合し、不足の有無を判定する。
- **足りない新作LINE画像は、この22:15の準備時点で制作する。** 素材が揃えば新規制作しない。新作は公式販売ページと本人作品IDを先に確認し、使用トーク例2～4種と一覧1枚を目安に制作する。
- 画像生成・画像合成が実行可能なときは、完成した実画像を `stamps/reuse/<sticker_id>/` に保存。GitHubの画像バイナリをコミットし、`stamps/reuse/<sticker_id>/manifest.json` に作品ID・出典・権利・SHA-256・画像種別・検証日・販売URLを記録する。
- 画像URLを読戻しし、実ファイル・SHA-256・内容・作品IDの一致を確認して初めて `approved` とする。生成未実行、画像API利用不可、アップロード不可、権利不明の場合は `blocked`。**指示を書いただけでは自動画像生成・自動アップロードの実装完了を意味しない。**
- 当日の投稿・予約済み画像の重複は禁止。使い回しは別日に限る。同一JST日のトーク例・一覧が共に未使用であることを確認してから翌日の投稿に使う。

## 2026-11-19補足：22:15の翌日分重複チェック対象

22:15の準備タスクで「同日画像の再使用禁止」という場合、チェックするのは**準備日Wではなく翌日の投稿日D（JST 00:00〜23:59）**。Dに既存予約された画像と、今回のD向け6件のLINE投稿内で重複しないことを確認する。育児・美容のD投稿とも同一画像を二重利用しない。**Wやそれ以前に利用した画像はDに再利用してよく**、過去利用だけを理由に追加生成しない。明示的な再利用禁止、実作品・権利・画像実在の条件は維持。
